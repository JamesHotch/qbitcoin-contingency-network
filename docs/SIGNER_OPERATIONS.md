# Checkpoint Signer Operations

## Local Development Mode

Docker Compose starts eleven separate signer processes with signer IDs 0 through
10. Each derives a distinct deterministic development ML-DSA key. The public
keys are committed by development chain parameters.

```text
DEVELOPMENT COMMITTEE ONLY:
All checkpoint signers share one operational failure domain.
This configuration provides no organisational decentralisation.
```

The keys are public test material. Never reuse them outside valueless local
networks.

Each `/v1/sign` request requires a bearer token from the ignored
`.env.devnet` file. Before signing, the process checks proposal chain and network,
queries its configured node, checks node stage and chain ID, fetches the
historical block, and compares the block hash.

Stop signers to test quorum loss:

```bash
docker compose stop signer0 signer1 signer2 signer3 signer4
```

Five unavailable signers leave six and therefore no checkpoint quorum. Mining
continues.

The deterministic attack demo exercises malformed signatures, six-of-eleven,
equivocation, cross-network replay, and a compromised single signer:

```bash
./scripts/attack-demo.sh
```

## Distributed Mode Requirements

Distributed mode is not implemented. It requires:

- Independently administered full nodes and signer hosts.
- Nondeterministic encrypted signing keys generated by each operator.
- Out-of-band public-key verification before genesis or rotation.
- Mutually authenticated encrypted transport.
- Durable anti-equivocation journals and offline audit exports.
- Hardware-backed key custody where suitable ML-DSA devices exist.
- Least-privilege services, rate limits, monitoring, backups, and incident plans.
- No common cloud account, credential, administrator, or deployment pipeline.

The committee must not sign an unvalidated block or rely solely on a proposal
coordinator's node.

## Rotation Status

Rotation metadata exists in chain parameters, but rotation consensus is not
implemented. Do not attempt ad hoc key replacement. Any future rotation must be
authorized by the old M-of-N committee, delayed, count-limited, public, and
incapable of changing committee powers or retirement.

## Incident Rules

- A signer that may have signed conflicting hashes should stop and preserve its
  journal.
- A leaked local test token should be regenerated by resetting the devnet.
- A suspected production-style key leak is not recoverable through an
  administrator override; the network is not ready for such keys.
- Report implementation vulnerabilities privately under `SECURITY.md`.
