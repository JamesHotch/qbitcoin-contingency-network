# Regulatory Boundaries

This document is a risk boundary, not legal, tax, accounting, or investment
advice. Rules vary by jurisdiction, facts, operator role, user location, and
time. Obtain qualified advice before activities beyond private valueless
research.

## Repository Scope

The repository provides open-source testnet research. It does not:

- Sell QBTC or solicit investment.
- Promise profit, liquidity, utility, exchange listing, or price.
- Back QBTC with BTC, fiat, assets, services, or redemption.
- Process fiat payments.
- Provide custody, brokerage, exchange, or money transmission.
- Operate a public token sale or mainnet.

Code availability does not determine legal classification and does not make a
project investment-ready.

## Activities Requiring Separate Analysis

- Public promotion, distribution, sale, airdrop, or fundraising.
- Custodial wallets, hosted keys, recovery services, or pooled funds.
- Exchange, brokerage, market making, payment processing, or redemption.
- Mining pools, hosted mining, fee sharing, or treasury distributions.
- Paid APIs, hosted nodes, enterprise wallet services, or user analytics.
- Collection of identity, network, transaction, sanctions, or tax information.
- Operation across borders or for restricted persons and territories.

Potential regimes include securities, commodities, money transmission,
payments, consumer protection, advertising, sanctions, AML/KYC, privacy,
cybersecurity, tax, and recordkeeping. This list is not exhaustive.

## Treasury

Any development treasury changes the economic design and can create recipient,
governance, disclosure, fiduciary, tax, sanctions, and fundraising questions.
Mainnet treasury terms and recipients are intentionally unset pending public
economic and legal review.

## Communications

Contributors and operators must not describe QBitCoin as quantum-proof,
audited, guaranteed, risk-free, investment-ready, objectively more secure than
Bitcoin, or guaranteed to retain value. Demonstration coins should be clearly
labeled valueless test assets.

## Privacy

Public ledgers expose transaction relationships. Node APIs, peer addresses,
wallet services, dashboards, logs, and hosted infrastructure can add personal
data. A public deployment would need data-flow mapping, retention rules,
security controls, user notices, and jurisdiction-specific privacy review.
